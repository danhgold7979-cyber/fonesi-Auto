## 1. Useful scope and smallest request

Original P2-06 (`docs/04_MASTER_IMPLEMENTATION_PLAN.md`) requires model, manufacturer, Android version, SDK, locale, resolution, density, battery and storage. Current parser, typed query, actor and sealed owner already cover exactly these nine fields. Add one explicit **Read candidate field** interaction and a cached metadata panel for one explicitly clicked Fleet candidate row, without changing the V9 layout/tab order. The field selector is the closed set MODEL/MANUFACTURER/OS/SDK/LOCALE/RESOLUTION/DENSITY/BATTERY/STORAGE. One click requests **one field**, not a batch, background sweep, selection-triggered read or automatic retry. Nine-field batching would introduce sequencing/partial-batch policy and multiply effects unnecessarily; all nine remain independently available through the same fixed operation.

`metadata.get` means captured process-local facade cache only, including while a Read is pending. Never call owner.snapshot from GET: that method may invoke clock/current callbacks and invalidate its own state. GET may use only already captured callback-free target/current witnesses and facade internal flags to return a conservative stale copy; it cannot refresh observations or amend owner state. It must not call owner.read, create an owner, inspect a device, start/refresh the server, acquire another runtime lease or renew a stale target. Initial document hydration may get cached status once; there is no periodic polling. After a PENDING response, a separate explicit Read status reconciles the result. The client never repeats the effect after timeout or a late response.

Snapshot exact proposed base keys (plus source/evidence below): `{revision,state,deviceId,registryRevision,operationId,field,lastOutcome,code,observations}`. States EMPTY/PENDING/READY/STALE/FAILED/OUTCOME_UNKNOWN/CLOSED. Initial EMPTY: revision0, null device/registry/op/field/code, lastOutcome NONE, all nine observation slots null. No raw output/serial/transport IDs in renderer or audit. Only the current owner slot's nine entries are retained; old target values are not copied to a new target. Captured-time state is not continuous health. Final response publication may mark captured entries stale/deny delivery after loss; it cannot assert currentness from an old cache.

### Exact cache/state and revision distinctions

The public registryRevision is the Fleet/RegistrySnapshot projection revision, **not** durable ledger revision or host_epoch. Capture those latter values only in the sealed private witness. A DISPLAY/other durable mutation can invalidate that witness without changing visible projection rows; return stale/REFRESH_REQUIRED, never renew from matching row text. Metadata interaction revision is a third independent counter; metadata request sequence is not discovery sequence.

Snapshot lastOutcome is NONE/PENDING/OBSERVED/NOT_DISPATCHED/DISPATCHED_UNCONFIRMED/OUTCOME_UNKNOWN. Codes are null only for NONE/PENDING; terminal OBSERVED uses OK, others a closed non-OK code. EMPTY is revision0, null candidate/op/field/registry/code, NONE and nine null slots. PENDING at R+1 binds candidate/op/field/projection with code null. READY at R+2 requires exact actor OBSERVED/OK plus final current witness; the field may be available **or unavailable**. FAILED at R+2 retains exact actor NOT_DISPATCHED or DISPATCHED_UNCONFIRMED and code, never invents a remote completion. STALE preserves historical lastOutcome, code and operation/field correlation exactly, but sets every existing field stale after target/projection/session loss. Freshness is orthogonal: do not overwrite a historical OBSERVED/OK or failed-operation code with a new loss code; any current request refusal carries its loss code in the error envelope. OUTCOME_UNKNOWN is sticky actor uncertainty; CLOSED likewise preserves historical lastOutcome/code/operation correlation with stale entries, not an assertion that actual work retired. Closure before any operation retains NONE/null correlation. All states keep exactly nine fixed keys, no fabricated value/time for null/unavailable entries.

The owner exposes coarse ActorResult, not raw query facts: COMPLETE nonzero/stderr and some QUERY failures both produce DISPATCHED_UNCONFIRMED/TRANSPORT_FAILED. Preserve that tuple; do not infer a remote exit or proof of wire handoff. Owner/target currentness separately controls cache eligibility. Unsupported battery/other text may truthfully remain unavailable; this proposal does not add parser profiles, fallback commands or promise nine available values.

Known BUSY before reservation preserves cache/revision. BUSY after accepted reservation terminates NOT_DISPATCHED/BUSY and preserves prior values using captured-time cache, never inspection-sensitive OBSERVED authority. Stop supersedes operation generation synchronously and stales/closes cache; late historical results cannot overwrite it. GET does not advance revision. Reserve room for pending and terminal increments before callbacks; safe-integer exhaustion refuses effects. Stop invalidation never depends on allocating a new counter or UUID. At most128 validated Read request IDs per launch, including denied admitted requests; duplicate IDs refuse without replay. Malformed requests allocate none. GET allocates no effect operation/history entry; it still obeys shared IPC/log bounds. Counter bounds do not increase native128 queries or ticket65536 issuance.

Renderer row selection is **context, not main authority**. Request deviceId is an eligible candidate under exact current projection, not an implicit requirement that it equal mutable Fleet active selection. Renderer captures its own row-selection generation plus request generation and discards A's reply after user changes to B. Main never changes Fleet selection, trusts a selection-derived serial or publishes A data tagged as B. Source-only eligibility and actual device permission remain distinct as §3 states.

## 5. Admission, audit and publication

Reserve operation generation/identity and busy state before any injectable owner/clock/logger callback. Capture request descriptors and immutable target context before await. REQUEST INTENT must flush before an accepted effect reservation is acknowledged; EXECUTION INTENT must flush before owner.read. Audit failure cannot dispatch a query. The retained server has no metadata-specific audit callback today: do not fabricate a TRANSPORT barrier or synthetic AVAILABLE result.

The next unused current log schema is **10** (current discriminator ends at9). The outer record is exact `{schemaVersion:10,runId,sequence,utc,severity,component:'MAIN',task:'P2-06',event:'METADATA',metadata}`; existing run/sequence/UTC/size validation remains. Inner exact keys: `{operation,stage,phase,diagnosticId,operationId,field,expectedRevision,resultingRevision,outcome,code}`. Diagnostic UUID differs from operation UUID; REQUEST and EXECUTION use separate diagnostic pairs, same operation and original metadata CAS. Severity INFO only for OK, otherwise WARN. No TRANSPORT pair or schema10 STOP; existing schema9 Stop includes metadata actual drain.
