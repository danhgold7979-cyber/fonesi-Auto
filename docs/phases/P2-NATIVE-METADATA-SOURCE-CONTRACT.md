## 4. Exact smart-socket / shell-v2 producer

Use the same owned loopback endpoint and retained foreground attempt as DISCOVER, never localhost default port/PATH/new adb process. On one registered socket:

1. Recheck process/listener ownership after connect and immediately before transport-selection send. Recheck the actual retained process handle, owned endpoint/listener and current custody again after the selection acknowledgement and immediately before the shell-command send, and before publication. Do not reuse a cached health result as the second handoff check. Send length-prefixed ASCII `host:transport-id:<canonical uint64 decimal>` and require exact OKAY. Never transport-any, USB-any or serial fallback.
2. These are bounded pre/post observations, not an atomic proof that a TCP peer can never change between observations; the socket is never reconnected/reselected and target loss closes it. On that same switched socket send length-prefixed `shell,v2,raw:<table literal>` and require exact OKAY. Unsupported service/FAIL is failure, not shell-v1 fallback. No feature query is needed to justify fallback; there is none.
3. Read shell packets incrementally: one channel byte, four little-endian length bytes, then exact payload. Only stdout(1), stderr(2), exit(3); exit length exactly one byte and exactly one exit. Require remote exit followed by clean EOF; duplicate exit, post-exit bytes, unknown channel, invalid lengths, incomplete header/payload or deadline abort rejects.
4. Bound and strictly decode UTF-8 text (no BOM/NUL), capture completion time before close, close and prove actual socket/connect/worker settlement, then final ownership/deadline checks. Remote exit is named `remoteExitCode`; it is never the helper's/local process exit. On cancellation, local socket/worker retirement does not prove that a remote shell process has exited. Do not report remote cancellation success from a closed local socket; without the exit packet, remote completion remains unknown. No remote kill/reset command is introduced.
