## 1. Policy and exclusions

CURRENT associates a unique PROVISIONAL/DEVICE record with the handset physically held by the trusted operator. HISTORICAL associates a unique IDENTITY_REQUIRED native candidate with an explicitly chosen DISCONNECTED historical record, with an additional same-handset attestation. Record selection, serial, transport ID, RSA authorization, receipt digest and native dialog appearance alone are not physical proof. The assurance is explicitly human-assisted and sampled, not cryptographic identity or continuous device health. Known disconnect, offline, conflict, epoch loss or restart revokes authority; there is no automatic continuity or serial-based relinking.

A successful actual association can satisfy the existing VERIFIED + DEVICE main metadata gate. This is a consequential permission transition and must be visible in the confirmation wording. Input admission, actor ownership and input activation remain unchanged; no input command, metadata query, test command, installer, shell string, screenshot or hidden device action is part of this ceremony. Main metadata still requires its own explicit Read. No automatic server start, refresh, query, polling or retry is introduced.

## 7. Proposed finite audit grammar
