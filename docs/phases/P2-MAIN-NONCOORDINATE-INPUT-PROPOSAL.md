## 1. Original scope and actual policy

[Phase2 P2-07/08/10](PHASE-02-adb-device-fleet.md) requires one serialized actor per device, correctly scoped input, and an active-control target distinct from the selected set and groups. This proposal integrates exactly HOME, BACK, ENTER, ESCAPE, DPAD_UP, DPAD_DOWN, DPAD_LEFT, DPAD_RIGHT and DPAD_CENTER. One deliberate click requests one fixed action on the actual main-owned ACTIVE target, which must be VERIFIED and DEVICE with a unique current native binding. A renderer deviceId is a consistency assertion, not permission to select another target. No selected-set/group broadcast, coordinate input, TAP/SWIPE, TEXT, arbitrary keycode/arguments, key repeat, auto-input or background retry.

Metadata retains its existing explicit candidate targeting; it does not suddenly derive its target from ACTIVE. Input derives ACTIVE from the actual Fleet selection controller. Human association remains session-scoped and known-loss-revocable; serial/RSA/model/receipt hashes never substitute for identity. Input does not weaken VERIFIED admission or manufacture identity. A source implementation can connect these existing policies; actual phone actions and profile/server execution remain excluded pending their real acceptance gates.

The existing native fixed mapping still uses keyboard/display0. App display:null is not an unspecified display: it means no coordinate evidence is required for these fixed keys. Remote exit0 plus socket settlement is **DISPATCHED_UNCONFIRMED/OK**, not OBSERVED or proof that Home opened, Back navigated, an app changed, or Android accepted an effect. P2-08 physical before/after evidence remains unmet by this source slice. One conservative facade-owned device at a time also does not prove full P2-07 independent-device concurrency.

## 3. Sealed per-request ACTIVE intent

Main captures the exact existing main-owned Fleet service instance once when constructing the facade; no replaceable service/current callback is accepted. The proposed capture method is main-private, not a renderer capability grant. Fleet owns a private WeakMap of `OwnedFleetActiveIntent`; no public registration, caller proof, mutable selection callback or optional input fallback. A narrow main-only `captureActiveInputIntent` method takes exactly `{expectedSelectionRevision,expectedRegistryRevision,deviceId}` against the actual service's current registry/selection. It runs ordinary ownership/current projection admission, calls its own selection controller with fixed ACTIVE/null group, and requires exactly one current VERIFIED/DEVICE binding and exact deviceId equality. It captures the recognized registry projection object, actual selection snapshot/plan identity, selection revision and sole `{deviceId,bindingId,generation,serial}` tuple. It cannot issue SELECTED/GROUP scope.

The capture returns exactly `{ok:true,intent}` or `{ok:false,code}`, with closed capture codes `CLOSED|BUSY|STALE_SELECTION|STALE_REGISTRY|NO_ACTIVE_TARGET|MEMBER_UNAVAILABLE|OWNER_REVOKED|LIMIT_EXCEEDED`. Exported inspect-only `inspectFleetActiveInputIntent(unknown)` returns null or the immutable record `{projection,selectionRevision,binding,finalCurrent}` for genuine tokens; binding is the exact four-field sole CurrentBinding tuple. No caller supplies finalCurrent. Its callback-free `finalCurrent()` reads only the owning Fleet service's actual closed flag and selection controller's captured-plan identity/revision; it must not invoke registry/options/owner/ViewSession/clock callbacks. Ordinary capture checks and final internal checks are distinct. Any selection replacement, including A→B→A with a new selection revision, invalidates an older request's token. An unchanged selection request does not invent a new selection generation. Fleet close invalidates all outstanding intents. Existing Fleet per-capability revocation is not an invented global revoked flag: this main-private capture does not borrow a short-lived IPC capability. Returning/releasing the PENDING IPC request must not revoke the intent. The facade independently captures and retains actual host/ViewSession generation fences for the whole operation; session/host loss invalidates delivery and dispatch even when Fleet selection is unchanged. Ordinary ViewSession/session liveness is also retained independently by the facade; this token does not replace session admission or native target provenance.

One token per admitted press, consumed once by the combined owner before callbacks. Consumption binds it to that exact command's private `inputWorks` record; it remains valid for that one active command until settlement/revocation and cannot authorize another press. Failed construction/dispatch does not return a usable token. Use the existing launch ID/operation bounds (65,536 cumulative IDs and 128 owner operations), never an unbounded issuance cache or a fresh parallel allowance. Actual effect admission refuses before allocation when exhausted; GET uses the existing bounded request counter discipline.

The owner must compare the token's exact projection and full tuple with **both** genuine native target records and their common anchor. Current private target inspectors expose numeric registryRevision but not projection object identity; proposed narrow addition is readonly `projection: RegistrySnapshot` to both private inspected records, captured from their existing issuer context. This exposes no renderer field or minting authority. Equal revisions or copied objects do not substitute for identity. The existing input ticket still supplies actual native row, nonnull transportId, host epoch and installation/custody fences. A synthetic/structural Fleet service or plan cannot manufacture the independent native tickets.

### Mandatory propagation beyond the owner

An owner-only check is insufficient: server query entry schedules a microtask and adapter awaits custody.revalidateRead before bridge input. Therefore the exact opaque intent must travel in the private TypeScript input call path through ingestion input record, server, factory and adapter. It is descriptor-captured before awaits and checked after all ordinary admission callbacks and immediately before actual `bridge.input` handoff. Source-derived final interval: adapter awaits custody.revalidateRead, then calls current(cap, owner), which itself invokes owned/admit/owned/assertRead/owned callbacks. Only AFTER that final current() and exact attempt/read-token recheck, call the captured callback-free actual held-token assertion, then the callback-free intent check, immediately before a.queries++ and the fixed input provider call. Extend the adapter custody Pick with the existing assertReadInternal and forward it through the factory tracked custody wrapper; this is not a new injected callback option. The tracked assertion may check captured token/runtime scalars but must call the real custody internal holder validation without ordinary owner/admission callbacks. This closes the final owned() callback gap after current() has already called assertRead: token object equality alone does not prove its holder remains valid. After these two final assertions, only internal checks may occur before input handoff. Checking before current() is insufficient. The existing INPUT bridge send contains no injected authority callback; factory initializeChild returns immediately for the already-running foreground child. Preserve that no-callback interval with a causal regression; a later selection change cannot retroactively prove the old command was not handed off. It is **not** serialized into v4 native JSON, not a new C# field or method, and not passed as an arbitrary finalCurrent callback. Factory/adapter import only the read-only Fleet intent inspector; Fleet must not import these execution modules. Metadata/discovery envelopes and native request bytes stay unchanged.

Proposed owner API becomes mandatory `input.press(action,deadlineUtc,activeIntent)`; omission/forgery is no-effect refusal. Owner records the exact token for that request. v4-only `ActorInputConfig.finalCurrent(request)` checks the matching inputWorks token instead of a mutable owner-wide active-selection slot. Existing v1/v2 and v3 callback signatures stay unchanged. Check after actual schema11 INTENT flush, after every subsequent external callback, immediately before query entry, after custody revalidation at final pre-bridge admission, and before fresh public delivery. The same owner remains reusable after selection changes via a newly captured intent only while its actual native/epoch authority remains current; selection is not a permanent owner-construction binding.

Exact proposed private signatures/envelopes are mandatory, with no optional argument, structural callback or legacy INPUT bypass:
- combined owner `input.press(action: InputQueryAction, deadlineUtc: number, activeIntent: OwnedFleetActiveIntent)`;
- inspected ingestion `InputTargetRecord.begin(action: InputQueryAction, deadlineUtc: number, activeIntent: OwnedFleetActiveIntent): InputQueryHandle`;
- server `OwnedInputRequest` exact `{requestId,epoch,sequence,transportId,action,deadlineUtc,activeIntent}` and `beginInput(request: OwnedInputRequest): InputQueryHandle`;
- factory and adapter `acquireInput(cap: HostCapability, request)` require exact `{transportId,action,deadlineUtc,activeIntent}`; descriptor normalization retains the exact opaque token identity, never copies/reconstructs its authority;
- v4 actor `ActorInputConfig.finalCurrent(request: InputQueryRequest): boolean`; its owner closure selects that exact normalized request's private `inputWorks` record and intent. Audit/dispatch keep their existing request argument; metadata's finalCurrent signature remains unchanged.

Each INPUT layer rejects missing/forged intent before its next handoff and repeats the inspector's callback-free witness at its final admission fence. The adapter strips only the private intent when calling the existing fixed native input callback `(attempt,transportId,action,deadlineUtc)`; bridge/native bytes remain unchanged. Existing low-level synthetic tests must use an explicitly transformed genuine-issuer seam, never an optional witness bypass. These exact additions preserve the acyclic inspector dependency; existing source does not already provide this propagation. Intent loss before known handoff refuses; after entering the reserved QUERY path use existing conservative native query mapping, not a retrospective no-dispatch assertion. A selection change found after QUERY reservation, including during held custody revalidation with zero bridge calls, retains the existing conservative failure/epoch-cleanup semantics; it is not newly classified LOCAL_REFUSAL. That owner cannot simply be reused after cleanup. No native protocol widening is needed.

## 4. Owner replacement, admission and one deadline

Preflight actual Fleet ACTIVE/CAS, native tickets, common anchor, consumed-ticket history, logger and owner identity before closing an existing owner. If same owner/target/projection remains current, reuse it for another metadata field or press; do not reacquire an actor. If a different target requires replacement, close/drain the previous combined owner before constructing one new owner. Claim both tickets before constructor callbacks and retain any returned owner despite reentrant Stop. Never construct after the request's original deadline or session generation is lost.

A→B→A after owner replacement in the same projection is REFRESH_REQUIRED before closing B: A's tickets are consumed. No remint or automatic Refresh. An ACTIVE selection change A→B→A while owner A was never replaced permits a fresh request/intent for A at the new selection revision; the old request's intent remains stale. Explicit new native discovery projection can issue fresh tickets only under the existing rules. Association, Refresh, runtime loss and known binding/epoch changes invalidate target authority and captured currentness; no serial lookup reacquires it.

One original absolute30,000 ms deadline begins at facade press admission. It covers replacement, actor queue wait, schema11 INTENT, query and result processing; no reset at owner construction, actor handoff or audit completion. The facade reserves tracked work before any callback/constructor. The combined owner additionally exposes a callback-free readonly `pending` getter derived from its private logical-work count plus actual actor.snapshot().active/queued. A logical receipt may arrive while actual RESULT audit/actor work is still held; clearing facade busy is not proof of drain. Every subsequent ordinary facade effect—metadata, input, discovery and association—must also refuse BUSY while this owner pending witness is true. Cached status GET remains usable. Stop retains the existing actual owner drain; no polling, replacement actor or second receipt is introduced. Shared busy plus this actual-work witness prevents concurrent main discovery/metadata/input effects; Fleet selection itself may change, and the per-request intent must safely catch that change rather than block all selection UI.

The facade deadline fences only pre-owner replacement/construction and known no-query work. Once `owner.input.press` has been entered, the actor owns that same absolute deadline; the facade must not independently timeout into UNKNOWN. It awaits the owner's one logical receipt while retaining actual owner drain. The owner preserves a known query candidate across held RESULT audit. If the owner logically returns UNKNOWN, it does not expose a second later known receipt: this proposal promises no such append or recovery.

An immutable PENDING acknowledgment reports reservation only, with DEGRADED until actual audit evidence exists. It must be validated/captured before starting a continuation that may fail synchronously. Existing client2,000 ms delivery timeout does not cancel the command, prove it was not dispatched, or authorize retry. Explicit Get reconciles; no polling or automatic second press.

Stop/revoke installs cleanup/report/generation latches before callbacks, closes owner admission immediately, and retains actual actor/native/audit/replacement obligations. The same existing120,000 ms cleanup/report scope remains; no fresh sequential timeout allowance. Abort/cancel is not Android undo. A known command result remains historical while RESULT audit or delivery is pending. A logical deadline before query entry is known no-query, but still retains an unsettled audit/constructor obligation. Query uncertainty remains sticky and starts existing epoch revoke/cleanup; do not invent a remote-process kill acknowledgment.

## 5. Proposed wire and public captured snapshot

Channel `foundation:input:v1`; one strict JSON string, exact keys, duplicate/extra fields refused, both string length and UTF-8 size <=16,384. No event/intent/handle/serial/transportId/epoch/argv/proof/raw output crosses IPC. Request IDs follow existing `p` + positive-safe-integer counter convention (<=17 characters); counters never wrap. Canonical main IDs remain UUIDs with existing fixed bounds.

Requests:
- `{version:1,requestId,method:'input.get'}`.
- `{version:1,requestId,method:'input.press',expectedRevision,expectedSelectionRevision,expectedRegistryRevision,deviceId,action}`.

Three revisions have distinct meanings: expectedRevision is facade input interaction CAS; expectedSelectionRevision is actual Fleet selection CAS; expectedRegistryRevision is the exact captured registry projection revision. None aliases durable revision, host epoch, native transport ID, command sequence or current owner generation. deviceId must equal the one actual ACTIVE plan member; it never overrides it.

Responses:
- `{version:1,ok:true,requestId,outcome:'STATUS'|'PENDING',snapshot,loggingHealth}`. STATUS means cached snapshot observation only. The input wire does not use OBSERVED at all, avoiding confusion with physical effect; lower ActorResult enums are not broadened.
- `{version:1,ok:false,requestId,code,loggingHealth}`; requestId nullable only for unparseable/unavailable ID. Boundary failure does not erase retained lower history.

Snapshot exact `{revision,state,operationId,deviceId,generation,selectionRevision,registryRevision,action,deadlineUtc,receipt,code,current}`:
- state `EMPTY|PENDING|SETTLED|FAILED|OUTCOME_UNKNOWN|STALE|CLOSED`.
- EMPTY: revision0, identifiers/revisions/action/deadline/receipt null, code null, current false.
- PENDING: admitted operation UUID, original device/generation/selection+registry revisions/action/deadline, receipt null, code null, current false; revision R+1.
- SETTLED: exact captured owner receipt with ActorResult NOT_DISPATCHED or DISPATCHED_UNCONFIRMED; code equals actual actor code, no OBSERVED input. `current` true only if all callback-free original intent/native/session witnesses remain valid at publication.
- FAILED: fixed pre-owner/pre-query refusal after reservation, receipt null; no invented actor command IDs or audit evidence.
- OUTCOME_UNKNOWN: the actual one owner/actor unknown receipt, code OUTCOME_UNKNOWN, current false. There is no independent facade post-owner timeout and no fabricated second late receipt; actual owner drain remains retained even after its logical UNKNOWN receipt.
- STALE/CLOSED: preserve original operation/target/action and actual receipt/code; current false. CLOSED before any press preserves EMPTY's all-null context and revision0. Pre-reservation refusal leaves history/revision unchanged. Freshness is orthogonal to historical outcome: callback-free loss at GET downgrades only returned current to false, without changing state/revision/history. An explicit captured lifecycle transition to STALE/CLOSED after settled work advances the current revision once; repeated same-state invalidation is unchanged. Pending Stop uses the reserved R+2 rule below. Never retarget old result to the newly active row.

Receipt, when present, is the unchanged owner envelope `{version:1,evidence:'NATIVE_INPUT_QUERY',actor:{outcome,code,commandId,correlationId,diagnosticId:null},loggingHealth}`. Copy it descriptor-safely at actual settlement. NOT_DISPATCHED or the actual early OUTCOME_UNKNOWN refusal may have both command/correlation IDs null before allocation; DISPATCHED_UNCONFIRMED may not. Otherwise both are canonical, distinct UUIDs matching the actual captured actor receipt, not equal to each other. No finer remote-exit receipt or Android post-state is invented. A successful query yields DISPATCHED_UNCONFIRMED/OK. Known query nonzero/output or stale target retains existing ActorCode mapping; do not infer partial physical effect from it.

Interaction revision reserves R+3 headroom. Admission publishes R+1; normal terminal R+2. Stop while pending captures CLOSED/currentfalse at R+2; the one actual owner receipt arriving after Stop appends original receipt at R+3 with CLOSED/currentfalse, not a replay or new command. If the pre-owner deadline already published FAILED at R+2 while replacement/drain work remains retained, subsequent Stop advances once to CLOSED at R+3; later pre-owner drain completion has no owner receipt and leaves that entire historical snapshot unchanged, rather than rewriting fields at the same revision. If result was already captured before Stop, preserve it; do not overwrite known DISPATCHED_UNCONFIRMED with UNKNOWN solely because an audit is still pending. New input admission waits actual prior drain; repeated Stop is unchanged. A selection change invalidates freshness through the captured intent, not by silently replacing cached target or allocating a new operation. GET returns captured-time history and callback-free currentness only, with no native query, owner.snapshot, new target capture, clock or custody revalidation.

Boundary error codes are closed: `AUDIT_UNAVAILABLE|INVALID_REQUEST|OWNER_REVOKED|BUSY|STALE_BINDING|STALE_DISPLAY|UNICODE_UNAVAILABLE|DEADLINE_EXCEEDED|CANCELLED|BINARY_UNAVAILABLE|TRANSPORT_FAILED|OBSERVATION_REJECTED|OUTCOME_UNKNOWN|CLOSED` plus `INVALID_TRANSPORT|PAYLOAD_TOO_LARGE|INVALID_JSON|INVALID_SHAPE|UNSUPPORTED_VERSION|UNKNOWN_METHOD|UNTRUSTED_SENDER|SESSION_UNAVAILABLE|SESSION_REVOKED|STALE_REVISION|STALE_SELECTION|STALE_REGISTRY|NO_ACTIVE_TARGET|MEMBER_UNAVAILABLE|REFRESH_REQUIRED|LIMIT_EXCEEDED|INTERNAL_FAILURE|TIMEOUT`. OK is never an error code; it remains valid only in an actual lower receipt. Keep exact lower actor codes in receipts; boundary mapping may not fabricate a different actor outcome. No error message/stack/native bytes are returned.

## 6. Audit and honest result mapping

Existing schema11 actual owned input INTENT/RESULT is the **sole effect audit**. Do not add a facade INTENT barrier with a second alleged input outcome, duplicate command receipt, or synthetic AVAILABLE callback. The combined owner already binds the actor-normalized full request, allocates its diagnostic pair lazily and records actual commandId/correlationId. Retain its one RESULT-attempt latch. A failed INTENT refuses query; an unsettled actual audit promise remains in drain. An append/sync failure leaves the actual logger degraded; known query history remains known, never rolled back.

Proposed GET audit policy is explicit **no new semantic audit record**: it reads the cached input snapshot only. loggingHealth is the retained actual owner receipt health, or DEGRADED before any receipt/audit confirmation, combined conservatively with actual logger broken/closing status through an existing captured read-only witness. It must not allocate a fake schema11 diagnostic or turn a later successful unrelated log call into AVAILABLE for a failed input RESULT. If product requirements demand status-access auditing, a separately named closed READ-only grammar must be reviewed; it is not silently added here.

Preserve adopted query mappings: LOCAL_REFUSAL means service-proven no query; native/wire BUSY is not automatically that case. QUERY reserves a path, not proof bytes reached Android. Dispatched failure without coherent remote completion, malformed result/retirement or logical query deadline remains conservative unknown/cleanup according to the existing actor. COMPLETE requires both actual result and coherent RETIRED obligation before it becomes a known command candidate. Zero exit is not UI effect evidence. No automatic retry after any ambiguous delivery or result.
