## 1. Useful outcome and explicit blocker

The useful local outcome is an actual owned SQLite registry → private metadata scheduler → existing DeviceActor → existing immutable metadata parser composition, driven exclusively by labelled synthetic process facts. It can prove targeting fences, queue isolation, stale-result refusal and bounded publication. It cannot prove actual metadata, device consent, physical identity or native retirement.

Two boundaries remain prerequisites to activation:

1. **Policy decision:** whether a uniquely observed PROVISIONAL transport may receive these fixed read-only property queries. This draft permits it only for SYNTHETIC_TEST construction described below. Actual-device permission remains unresolved; no resolver or identity promotion is invented.
2. **Honest native evidence:** DeviceActor v1 accepts a process result with exitCode/retired. A future retained socket operation has different worker/socket and remote-shell-exit evidence. This draft does not convert a socket reply into a fictional local process exit. Native integration requires a separately reviewed typed scheduling seam/evidence contract; until then the dispatch implementation is test-injected only and unavailable in product construction.

## 3a. Exact synthetic-only construction and tuples (proposed API)

This checkpoint exports **only** `createSyntheticTransportMetadataOwner(options)`. The name and every returned envelope carry fixed `SYNTHETIC_TEST` plus evidence `SYNTHETIC_PROCESS`; there is no `source`, `native`, provider-registration or native-brand option. No main/preload/renderer import, production availability change or native factory accessor is permitted. Real recognized snapshots must have `source === SYNTHETIC_TEST`, non-null sequence/time and matching synthetic bindings; an ADB_DISCOVERY snapshot is rejected even when recognized. PROVISIONAL is eligible **only in this synthetic contract**, subject to all unique DEVICE/target predicates. This is not authorization to query a real provisional device.

Constructor options are exact own data properties, snapshotted once: `{registry, hostEpoch, deviceId, ownerId, budget, now, assertOwned, dispatchSynthetic}`. `registry` is a recognized RegistrySnapshot; `budget` is the existing recognized DeviceQueueBudget; `deviceId` and `ownerId` are canonical lowercase UUID strings. Capture/bind all callbacks once. `assertOwned()` must return literal true. `dispatchSynthetic` receives the wrapper-generated immutable v1 DeviceMetadataRequest and returns the existing DeviceProcessResult promise; no native provenance is implied. No binary lookup is performed: this explicitly synthetic owner's actor binary-availability predicate means fixture availability only and never reaches product state.

The owner captures one target from registry at construction and creates a fresh private object-identity generation token; it never accepts a caller token. Exact public target record: `{deviceId,bindingId,generation,serial,transportId,hostEpoch,registryRevision,observationSequence}`. The opaque private generation token is deliberately not serialized. Numeric durable `host_epoch` (API spelling `hostEpoch`) is a positive safe integer and must remain equal; it is not the object token and not registry observationSequence. Registry revision and observation sequence are separate nonnegative safe integers. Capture all three independently. Current target matching requires the same device/binding/generation/serial/transport ID and hostEpoch, with the original or a later monotonic synthetic observation; a revision increase alone is not physical identity or automatic revocation if that exact target remains current.

Methods, and no others:

- `read(input): Promise<MetadataReadResult>`; exact readonly input `{version:1,commandId,correlationId,field,deadlineUtc}`. Target/owner are never supplied per request. `field` is one of the existing nine MetadataOperation literals. UUIDs are canonical lowercase, 36 characters. No input-operation shape is accepted.
- `updateRegistry(registry, hostEpoch): void`: explicit **synthetic fixture synchronization only**, accepting recognized SYNTHETIC_TEST state with monotonic revision/sequence/time. Tests first commit through actual SQLite/RegistryStore and then deliver that exact recognized snapshot. Reject malformed/regressive/foreign-source updates without adopting them. A changed hostEpoch or invalidated target irreversibly invalidates this owner's private generation; creating a new owner is required. The method cannot mint a native epoch or durable identity.
- `snapshot(): MetadataSnapshot`: no callbacks, no effects, returns already-frozen captured-time state; stale:false means current at its last successful publication fence, not continuous owner/native health or a fresh observation. It cannot turn a stale observation current. The current registry reference/epoch and revocation flags are private fields, enabling final checks without an external provider callback.
- `close(): Promise<boolean>`: idempotently revoke admission/queued work and retain the actual dispatch drain. The first close starts one captured 120000-ms reporting budget; repeated calls return the same report and never rearm it. True only after actual actor/work retirement; false is uncertainty, never permission to release unrelated runtime custody. Retain the actual drain promise separately after the report expires. `retired` is a readonly callback-free getter requiring every actual dispatch settled, every normalized result retired:true, no unresolved uncertainty and actor retirement, not the close report alone. Late genuine settlement may complete tracked JavaScript work but never reopen admission, reclaim actor registration, turn an uncertain actor shutdown into true, or rewrite the already returned report. An actor logical deadline/OUTCOME_UNKNOWN irreversibly latches wrapper UNCERTAIN; retired remains false even if later fixture work settles. This deliberately preserves the existing actor uncertainty policy. Malformed/rejected/unretired dispatch evidence has no fresh retirement confirmer in this slice: it remains sticky UNCERTAIN, even if its JavaScript promise has settled.

`MetadataReadResult` is the exact frozen record `{version:1,source:'SYNTHETIC_TEST',evidence:'SYNTHETIC_PROCESS',actor,observation}`. `actor` retains the existing ActorResult shape/outcome/code and null diagnosticId; invalid input retains its null correlation fields rather than guessing. `observation` is null unless final publication succeeds. A published observation is exactly `{target,metadata}` where `target` is the record above and `metadata` is the existing immutable MetadataResult. No raw stdout or callback is returned. Unavailable parsed metadata may be a truthful observation, never a fabricated zero; invalid envelope or failed current fences cannot publish.

`MetadataSnapshot` is exactly `{version:1,source:'SYNTHETIC_TEST',evidence:'SYNTHETIC_PROCESS',state,target,observations}` with state `ACTIVE|INVALIDATED|CLOSING|CLOSED|UNCERTAIN`; target remains the original target record, observations a fixed nine-key field map with each value null or `{target,metadata}`. Current publication uses current registry revision/sequence in its observation target, without rewriting prior observations. Invalidation/close marks retained metadata stale; it does not relabel its binding/epoch. Initial map is all null. Snapshot is bounded, deep frozen and has no exposed actor capability.

Bounds: one actor per owner/device in the existing budget; queue 64/device/shared 1024; at most nine stored field values. Command/correlation IDs must be distinct per owner, with a finite 128 accepted-request history; after 128, refuse further reads with BUSY (never evict/reuse IDs or renew authority). Use existing serial grammar (1–256 ASCII token characters) and canonical positive decimal transport ID up to uint64, without numeric precision loss. Generation/revisions/sequences are safe integers, never negative zero. `now()` and deadline are integral UTC milliseconds in `[0,8640000000000000]`, never negative zero; sampled time cannot regress within an owner. Deadline must be strictly future and at most 120000 ms from initial admission, and is never extended. Invalid clock/state fails closed. Each synthetic stdout remains at most 65536 UTF-8 bytes under the actor/parser limits; rejected raw data is not retained.

Exact wrapper failure codes reuse ActorCode only: malformed request/duplicate ID → INVALID_REQUEST; invalid clock/expired or excessive deadline → DEADLINE_EXCEEDED; owner false/throw → OWNER_REVOKED; changed target/epoch → STALE_BINDING; queue/history full → BUSY; closing/closed → CLOSED; malformed/rejected/unretired or unattachable entered dispatch → OUTCOME_UNKNOWN. Actor transport/nonzero/timeout outcomes retain their existing code/outcome, never upgrade to OBSERVED. When the unchanged actor has already entered its dispatch wrapper and that wrapper refuses its final fence before fixture handoff, throwing conservatively yields actor OUTCOME_UNKNOWN and sticky uncertainty. This is zero fixture handoff, not a fabricated NOT_DISPATCHED/retired-process claim; no actor change or synthetic successful result is used to hide that lifetime boundary. Constructor/update admission throws only fixed TRANSPORT_METADATA_OPTIONS / TRANSPORT_METADATA_STATE; no raw callback message. All invalid state updates latch invalidation before throwing. No synthetic binary failure is presented as an actual installed-binary observation.

Normalize descriptor-only and deep-copy the dispatch result at **its own actual promise settlement**, before invoking external parser/clock/publication callbacks. Capture intrinsic native-Promise attachment as the existing ingestion does; accept only the same bounded plain native-Promise discipline, no arbitrary thenable or overridden then/constructor dispatch handle. Attachment failure after dispatch entry cannot clear busy or prove retirement: latch unknown and retain the work/uncertainty. A valid result requires exact own-data process-result keys, bounded stdout, valid status/exit tuple and literal retired:true before publication. Promise fulfillment by itself is insufficient. The fixture result is SYNTHETIC_PROCESS; parser metadata source ADB_TEXT remains format attribution only.

At that validated result settlement, sample observedUtc once, requiring requestStartUtc <= observedUtc <= deadlineUtc and nonregressing clock; do not manufacture observedUtc at later publication. Recheck the deadline again before publication. Assign each admitted request an internal monotonic sequence (bounded by 128); an older request may never overwrite a newer field entry. The nine-entry map distinguishes: null = never observed; available:true/stale:false = current parsed value; available:false/stale:false = current unavailable observation with its exact fixed parser reason; stale:true = historical observation after target loss/close. Parsing invalid raw text yields the parser's truthful unavailable result only when transport/retirement/current envelopes are valid; invalid transport never publishes. Target invalidation marks all existing entries stale and cannot change their observedUtc or original target. Known pre-dispatch malformed/BUSY/expired refusal preserves the prior captured field observation unless owner/target loss is also detected. A dispatched, known-retired nonsuccess makes the prior same-field entry stale, without creating a value or timestamp. A valid transport whose text is malformed/empty publishes the parser's unavailable result. Owner-wide unknown, logical actor timeout, target loss and close mark all prior entries stale. No concurrent callback may mutate a frozen entry.

For final checks, read/capture external clock and owner callbacks first; then use only the private latest recognized registry, generation token and stopped/invalidated flags. Any callback-triggered update/close is visible to that final synchronous check. No external callback runs between final check and dispatch handoff/publication. This synthetic private state is a test authority only; it is not a substitute for the future real issuer's runtime custody witness.

## 4. Pinned primary protocol evidence and selected fixed scope

The following are inspected upstream source revisions, **not** a provenance claim that the distributed Google 37.0.1 executable or every OEM daemon was built from these commits. Different source pins are intentionally explicit.

- [AOSP SERVICES.TXT, a8ab5ce](https://android.googlesource.com/platform/packages/modules/adb/+/a8ab5ceccb41035804ad83bfa625adac4a8ccf83/SERVICES.TXT) describes switching a host socket to a transport and shell-v2 separation of stdout, stderr and exit. This does not establish support on an attached device.
- [AOSP adb.cpp, 327bdd5](https://android.googlesource.com/platform/packages/modules/adb/+/327bdd52c1107d2f87e283dc104f9171b2baa88b/adb.cpp) handles `transport-id:` by parsing the supplied ID and binding the selected transport to the socket. [transport.cpp, 7447d54](https://android.googlesource.com/platform/packages/modules/adb/+/7447d5485dfd1dcc4f090810cf67b33b9850599f/transport.cpp) selects by ID when one is supplied; it does not simultaneously establish physical identity from serial. The proposed fixed selection service is `host:transport-id:<canonical positive decimal>`.
- [AOSP client/commandline.cpp, 8823344](https://android.googlesource.com/platform/packages/modules/adb/+/882334464c178849d2322711424d2836d4593fe4/client/commandline.cpp) constructs shell services with protocol/raw arguments and interprets shell-v2 stdout/stderr/exit packets. The proposed fixed service profile is `shell,v2,raw:<one source-owned literal>`, without PTY, caller interpolation or fallback to shell-v1.
- [AOSP shell_protocol.h, 0e1749a](https://android.googlesource.com/platform/packages/modules/adb/+/0e1749ad8d981f81c77711096b01a8a632879115/shell_protocol.h) defines one ID byte plus four length bytes, stdout ID 1, stderr ID 2 and exit ID 3. [shell_service_protocol.cpp at the same revision](https://android.googlesource.com/platform/packages/modules/adb/+/0e1749ad8d981f81c77711096b01a8a632879115/shell_service_protocol.cpp) permits partial payload reads and copies the uint32 length. Proposed decoder scope is the explicit little-endian Windows/Android profile, not an assertion of universal endian portability.
- [Pinned AOSP getprop.c, 491035c](https://android.googlesource.com/platform/system/core/+/491035ce1ceec310f98347654ea17cafa6ccb520/toolbox/getprop.c) reads a named property and prints its value with a newline; absent values default empty. [Pinned Build.java, 906cf8e](https://android.googlesource.com/platform/frameworks/base/+/906cf8e8a65027314ff71e0895b5e7e2263f1cbd/core/java/android/os/Build.java) identifies the manufacturer, model and SDK property names. These property names do not guarantee nonempty, trustworthy or vendor-compatible responses.

For a future adapter, the currently researched property subset is only (three fields, not a claim that all nine acquisition commands have been verified):

| Field | Exact source-owned literal | Parser |
| --- | --- | --- |
| MODEL | `getprop ro.product.model` | existing MODEL |
| MANUFACTURER | `getprop ro.product.manufacturer` | existing MANUFACTURER |

No property enumeration, serial/fingerprint lookup, arbitrary getprop key, stdin, shell composition, quoting template, environment prefix, retries or mutation command. The SOURCE-only wrapper may exercise all nine existing fixed metadata operations against synthetic process results: they already share the same queue/parse/publication boundary and add no actual command authority. Existing OS/LOCALE/RESOLUTION/DENSITY/BATTERY/STORAGE parsers remain unchanged; this checkpoint does not claim their acquisition paths. A real nine-field command mapping would require additional primary format evidence before adapter entry, not guessed OEM fallbacks. The property subset above documents researched literals, not an artificial three-field product feature or a new executable command table.

## 5. Immutable framing and result boundary

**Future adapter requirements only; no decoder implementation or standalone framing tests in this source slice.** A future decoder must accept only copied bounded bytes and fixed success/failure framing. Selection and shell service acknowledgements must each succeed. Failures remain failures; no alternate target. Decode incremental five-byte shell headers across arbitrary chunk boundaries, enforce declared lengths before allocation, accept only stdout/stderr and a single one-byte exit packet, require exit zero, no trailing packets/bytes and completed stream. Unknown packet IDs, duplicates, truncated headers/payloads, invalid UTF-8, oversized output and nonempty stderr produce fixed unavailable/failure facts. A remote shell exit is explicitly named remote exit, not helper-process retirement.

Use at most 64 KiB aggregate stdout + stderr and 256 frames per operation; cap each declared payload at 64 KiB. Retain no raw bytes after parse/settlement. Copy/freeze the parsed value; `ADB_TEXT` describes the parser's format only, not native provenance. Empty text is unavailable, not a fabricated value. Existing parser limits remain in force. Framing completion alone cannot satisfy actual socket/worker retirement.

## 6. Authority, deadlines, retirement and publication

One explicit synthetic read requests one of the existing nine fixed metadata fields; no polling, batch traversal or automatic reconnect. Reuse actor queue limits (64/device, shared budget 1024) and existing maximum 120-second absolute deadline; do not reset it between queue, dispatch, parse and publication. One actual dispatch at a time per actor. Bound retained snapshots to the nine fields per admitted actor; no unbounded history.

Before scheduling, capture target/request/clock facts descriptor-safely and immutably. Immediately inside the dispatch wrapper repeat owner, request generation, absolute deadline and complete target checks after any external callback; finish with callback-free epoch/custody/closed checks before handoff. This closes the weaker v1 admission window without changing the input route.

The actor `observe` callback parses into a private candidate only: no DB write, public snapshot mutation or callback delivery. A logical actor deadline/unknown read response returns promptly with observation:null; it does not wait indefinitely for a still-pending dispatch. Retain that actual promise separately for close/accounting. Only the successful publication path, after actor completion and actual injected dispatch promise retirement, may repeat the complete target/deadline/owner checks, then callback-free final custody/generation checks and publish the immutable candidate. Do not invoke an external clock/owner callback after the final internal check. A valid parse followed by revocation is not an observation.

Stop, disconnect, epoch replacement, owner revocation or target generation change deny new work and revoke queued work. Track the actual dispatch promise independently of a timeout response. Actor shutdown returning false or a deadline firing is not native retirement; preserve uncertainty and do not release any surrounding server/runtime authority on that basis. Late results cannot replay, replace a newer binding, change a stopped snapshot or revive authority. A future native adapter must independently prove query settlement while preserving the live foreground session; query retirement is never server terminal evidence.

Keep process-local observations tagged with full target and observed time. On invalidation retain only a bounded stale historical value, explicitly not current; do not relabel it to a new target. No metadata SQLite table, DISPLAY insertion, identity proof or audit schema is silently added. The actual SQLite participation is registry authority/history and final admission, not claimed metadata persistence.

## 7. Runnable local proof and stopping condition

After separate source-entry approval, focused tests should compose the real SQLite adapter/RegistryStore, real DeviceActor and real parser. The transport is an explicitly injected synthetic process-result fixture; no spawned process, socket or device. Required causal cases:

1. Positive exact target, all nine existing fixed metadata operations, immutable parse/publication; no arbitrary operation or command accepted. Fixtures remain synthetic process evidence, never socket evidence.
2. Actual registry generation/reconnect transition and competing duplicate serial/transport claims invalidate queued and late results; epoch replacement also rejects an otherwise identical tuple.
3. PROVISIONAL policy is tested only if explicitly adopted, without modifying VERIFIED input admission; metadata success cannot authorize input or add identityEvidence.
4. Last owner/clock/target callbacks revoke immediately before dispatch and immediately before publication: zero handoff or no published result respectively.
5. Parse succeeds then owner/epoch changes; snapshot remains stale/unavailable. Caller mutation/accessors cannot change captured target/request/results.
6. Pending dispatch + timeout/Stop: no successor effect, shutdown does not claim retirement until the actual promise settles; late malformed/unretired result preserves uncertainty.
7. Independent actor queues and shared cap are exercised locally, without claiming parallel native queries (current native ordinary lane is shared).
8. Existing text parser boundaries remain causal: oversized/invalid/empty text, malformed units and caller mutation fail without publication. Future socket framing tests (split/coalesced headers, lengths, exit and UTF-8) are deferred together with the actual adapter, not implemented speculatively.
9. Actual SQLite rows/identity evidence remain unchanged by metadata reads; disconnected durable history is not silently reactivated.

Completion of this checkpoint means reviewed source and these synthetic composition tests only. Actual provider wiring, server/device/profile access, connected-device/OEM protocol evidence, real RSA/USB/wireless traces, verified physical identity, capture/input and packaged native metadata are excluded and remain unmet. If review cannot preserve honest synthetic evidence with the existing actor seam, stop at this draft and report that exact blocker rather than adding a generic abstraction.
