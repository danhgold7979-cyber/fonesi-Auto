## 1. Behavior and authority

After decoder/display failure or user Stop, detach only that display and retire its owned video. Preserve original finite error, actor/server/host epoch, target identity, requested settings and all custody fences. Only an explicit new Start may request a new video attempt; no automatic retry, Refresh workaround, actor replacement, device switching or reset of single-use flags. If retirement is uncertain, replacement remains unavailable. Native transport corruption can still trigger existing fail-closed owner shutdown; this is not classified as a harmless display-only failure.

Scope is coherent TS/native source plus pure/fake software evidence. Actual Windows synthetic, managed, paired/native and device campaigns remain separately reviewed. Existing v5/v6 behavior and all hardware gates remain intact. No new user preference is required; automatic retry/backoff would be a separate policy decision and is not proposed.

## 3. Exact v7 requests and results

All fields have current strict descriptor/ASCII/canonical-order/line-size constraints, no unknown keys. Existing UUID, safe integer, hash, transport, deadline and scid bounds remain. The enclosing sessionId and attemptId identify the retained server owner, not the new video.

START fields, in order:
`version:7, requestId, sessionId, attemptId, kind:"VIDEO_START", videoId, videoOrdinal, previousVideoId, transportId, hostEpoch, deadlineUtc, artifactId, scid, nonceHex`.
`videoOrdinal` is an integer1..128 consumed by every accepted-to-validation fresh START, including a NOT_STARTED refusal. `previousVideoId` is null for the first actual owner, otherwise the last successfully owned video's ID; a refusal does not change it. Native compares this predecessor against its captured slot. Each videoId/scid/nonce must be new within the retained bounded history; collision is NOT_STARTED/REJECTED, never regeneration after handoff or tombstone eviction.

STATUS/STOP fields:
`version:7, requestId, sessionId, attemptId, kind:"VIDEO_STATUS"|"VIDEO_STOP", videoId, videoOrdinal`.
Credit fields:
`version:7, sessionId, attemptId, kind:"VIDEO_CREDIT", videoId, videoOrdinal, creditId`.
Credit is flow control, not a new ordinary request. Valid current credit uses current strict credit sequence. Known retired credits may be discarded only against that exact old record and a bounded issued-credit range, with no mutation of current state; unknown identity/invalid range remains protocol failure.

Reply envelope preserves fixed `version,requestId,sessionId,attemptId,kind,result`. Every v7 video result has exact keys:
`handoff:"NOT_STARTED"|"OWNED", videoId, videoOrdinal, refusal:null|"BUSY"|"QUOTA"|"STALE_TARGET"|"REJECTED", snapshot:null|VideoSnapshot, fresh:boolean`.
- NOT_STARTED requires one refusal, snapshot:null and fresh:false; certifies no native provider video owner was installed and the registered admission/construction path is terminal. It never asserts a remote effect or prior owner retirement. It is distinct from a rejected/unknown transport promise.
- OWNED requires the unchanged strict VideoSnapshot whose sessionId equals videoId. A newly observed native result has refusal:null/fresh:true. An idempotent tombstone result has refusal:null/fresh:false. A quota-refused STATUS or post-receipt tombstone STOP read of an already-owned identity has refusal:QUOTA/fresh:false and the last validated cached snapshot for that exact owner; it is explicitly not a fresh health/retirement observation. Never report NOT_STARTED for an owner that was installed. OWNED means a native owner exists, not that a remote launch or frame succeeded. Its cleanup remains mandatory until proven retired.
- STATUS/STOP against a retained NOT_STARTED tombstone may return that same result without provider effects; against an owned record return its immutable current/final snapshot. Duplicate old Stop cannot target the current replacement. Unknown video identity is not a new owner admission.
- Exceptions/timeout after provider registration can never be turned into NOT_STARTED. Retain OWNED/UNCERTAIN or current protocol failure and cleanup obligation.

Existing app START/STOP IPC can remain structurally unchanged: map NOT_STARTED/BUSY to a truthful local BUSY; map QUOTA to terminal preview-unavailable until a separately authorized owner lifecycle is restarted; preserve existing PENDING/STOPPED/UNCERTAIN semantics without claiming retired native work from a renderer state. A source review must bind every lower discriminated result to these app outcomes before coding.

## 4. Native boundary budget — independent of main UI correctness

Per retained server attempt, v7 owns exact bounded accounting:
- `ordinaryUsed` U is integer0..128; `statusReserve` R is0|1 with exact reserved owner; `quotaNoticeReserve` Q is0|1 (initially1); invariant **U + R + Q <=128**. No reservation is extra quota. `ordinaryClosed` initiallyfalse. Counters never reset on replacement.
- A normal non-reserved STATUS or a BUSY/rejected START may be charged only when U+R+Q<128; then U increments. It cannot consume another owner's reserved STATUS unit. A STATUS for the exact reserved owner consumes R and increments U, preserving the invariant, even when ordinaryClosed is true. Further STATUS for that owner follows normal unreserved admission.
- Installing a fresh candidate requires two unreserved units before its START charge: one for START and one new R. Only after old owner is proved Clean may its unused R be released; no early release on Stop reply. Charge U++, then set R=1 for the candidate. If these units are unavailable, do not install a candidate.
- On the first request that lacks required unreserved capacity, consume Q (Q=0,U++) to publish one terminal QUOTA notice, set ordinaryClosed=true, preserve any other owner's R. START returns NOT_STARTED/QUOTA. STATUS or a post-receipt tombstone STOP read of an OWNED identity returns OWNED/QUOTA/fresh:false with its last validated cached snapshot and no new effects (never the first real cleanup STOP); never forge non-admission. A STATUS or cached STOP read of a NOT_STARTED tombstone may return NOT_STARTED/QUOTA/fresh:false. This reserved notice is inside128, not an extra response beyond the lifetime cap.
- Once ordinaryClosed, only the exact remaining reserved-owner STATUS is admitted as ordinary work. Further START/non-reserved STATUS is protocol misuse, not an unlimited QUOTA-response service. Host exposes the terminal quota outcome and disables ordinary preview requests; STOP/RETIRE remain admitted. Example U126,R1,Q1: a new START lacking capacity consumes Q→U127,R1,Q0 and cannot take the reserved unit; the mandatory owner STATUS then yields U128,R0,Q0. A state U127,R1,Q1 is invalid, never admitted.
- `nextVideoOrdinal`1..129: every fresh START admitted to validation (normal or terminal quota-notice START) consumes the expected next ordinal; mismatch/reuse cannot install provider effects. At129 no new START. Seen-ID/scid/nonce histories retain at most128 records, with no eviction/wrap. Ordinal exhaustion also uses the one reserved QUOTA notice and closes ordinary admission.
- `ordinarySlot`: NONE | ADMISSION(request) | RESPONSE_PENDING(request,result). Exactly one. Native itself enforces this before callbacks. An overlapping ordinary wire request is protocol misuse, not queued healthy-user retry; no effect/response allocation occurs and existing bounded fail-closed cleanup applies. UI reservation is defense in depth, not the native proof.
- `cleanupSlot`: NONE | STOP(owner,promise/result), independent of U/R/Q/ordinaryClosed, plus per-owner `cleanupReceiptUsed` boolean initiallyfalse. The first STOP of an installed/preparing owner reserves its single cleanup response obligation and latches the one actual cleanup; ordinary exhaustion never denies it. No second STOP response may be allocated while that cleanup receipt remains pending. Same requestId is strict replay; a new overlapping wire STOP is protocol misuse with no second effect/response and no renewed deadline. Parent RETIRE still owns internal cleanup regardless of such misuse. An unused R releases only after that owner's actual Clean witness.
- Application/TS repeated Stop reuses the captured promise/result and emits no additional wire request. After a native cleanup receipt was delivered, a fresh-requestId STOP for that retired identity is only an idempotent tombstone read: it must take the ordinary slot and an unreserved U unit (or the one Q notice), never consume another owner's R, create another cleanup effect or use a free cleanup response. At exhausted/closed ordinary admission it is protocol misuse, not an unlimited cached-reply channel. A terminal NOT_STARTED tombstone similarly needs ordinary accounting for wire reads; its local cached Stop needs no wire. Every native owner has at most one dedicated cleanup receipt; bounded history therefore bounds dedicated cleanup response obligations. A new active owner's first STOP remains independently serviceable even when old tombstone reads exhausted ordinary quota.
- `rejectionResponse`: zero or one fixed result obligation tied to ordinarySlot, not another encoded output queue. Encode/enqueue only when capacity exists; never increase OutputLimit2. Include it in supervised shutdown/timeout accounting. Reserved STATUS and dedicated cleanup are finite obligations, not authority to force output past its bound.

Replayed/nonmonotonic request IDs retain strict rejection. No loop continually emits BUSY or quota replies under held Flush. Protocol misuse can close the helper after owned cleanup; it is separate from the valid display-failure recovery guarantee. Every NOT_STARTED response remains conditional on no native owner installation; quota and freshness cannot rewrite actual ownership history.

## 5. Clean-retirement barrier and backpressure

No waiting while holding native protocol/provider locks. The exact old immutable owner must be captured and compared. Required witnesses:
1. Renderer decoder/port detached, canvas cleared and old delivery/paint promises terminalized by cancellation/rejection. Lost renderer ACK is not awaited and proves no native cleanup.
2. Consumer construction and START/STATUS/STOP work actually settled; captured actualPending0 plus strict terminal snapshot localRetired and CLEANED/NOT_REQUIRED. A timeout/rejection is not proof.
3. Exact native VideoState.Clean: actual producer joined, workerDone, cancellation task completed, io.Retired and shell/child/foreground-exit facts reflected in localRetired, !unknown, required settlement written, directory NONE or cleaned, launch NONE or EXITED. Inspect through a bounded internal capability; don't accept a caller boolean.
4. Native protocol old ordinary and videoCleanup workers joined, old media irrevocably cancelled, and no old producer can enqueue again. Capture media/owner in worker closures, including StartFinished finally; never read mutable current media there.
5. Under protocol gate: output queue empty, mediaFrame null, outstanding0, attempt.frames0, writeStarted=-1, !writingMedia, !writeFailed. Existing writer decrements only after Write+Flush completion; queued media may be removed/cancelled, an in-flight write may not be declared retired. Old unacknowledged credit debt is cancelled only after there is no live producer/queued/in-flight record.

Inspect terminal native Clean outside protocol gate using existing nonblocking semantics, then reacquire gate and atomically recheck captured owner + all protocol predicates. Terminal Clean is monotonic for that exact record. STOP reply cannot certify its own final flush; admission always repeats the native output barrier. If false, result is NOT_STARTED/BUSY and **never auto-admits later**. Reserve only that one rejection-response obligation until output capacity returns; reader cleanup remains serviceable, no Enqueue overflow and no new native owner. A hung writer retains existing real OUTPUT_TIMEOUT/UNRETIRED, not fabricated healthy recovery.

When barrier is true, register PREPARING(candidate,old-clean-tombstone) under protocol gate **before** provider callbacks, then invoke provider outside the gate. Provider CAS requires the same exact old native record still Clean and current, then publishes candidate before any launch/callback. Cancellation already has a captured candidate latch; late bind/installation after cancel immediately inherits cleanup. If provider or subsequent publication fails, retain candidate as an obligation until actual NOT_STARTED or clean retirement is established. Never restore an old clean tombstone and forget a possibly installed candidate. Shutdown between either gate must drain old bookkeeping and all candidate/native obligations.

Each fresh candidate has new videoId/ordinal/scid/nonce, port, decoder generation, captured registry revision/device generation, and original30s admission deadline. No reset of old record, deadline or global quota. Final device/custody/host epoch/target/artifact checks remain before handoff. No error is allowed to change target or actor identity.
